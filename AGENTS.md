are not backed by a file here.

## What this project is

`se-emulator-standalone` is a single-page SvelteKit app that emulates
StreamElements activity events. The user pastes a StreamElements JWT token, the
app reads their channel from the StreamElements API, and then fires mock events
(follow, subscriber, tip, cheer, raid, merch, community gift) to that channel's
activity feed.

- The JWT is read from and written to the browser `localStorage` key `se_jwt`;
  it is never sent to this app's own server (see `src/routes/+page.svelte`).
- The app calls the StreamElements API directly from the browser:
  - `GET https://api.streamelements.com/kappa/v2/channels/me` to resolve the channel.
  - `POST https://api.streamelements.com/kappa/v2/activities/{channelId}/mock` to send events.
  - Both live in `src/lib/api.ts`.
- Event types, form fields, and payload shapes are defined in `src/lib/events.ts`
  (`EVENT_CONFIGS` and `buildEventPayload`). A "community gift" send fans out into
  one `communityGiftPurchase` plus N `subscriber` events sharing one
  `activityGroup` (see `handleSend` in `src/routes/+page.svelte`).

## Stack

- SvelteKit 2 with Svelte 5 (runes mode: `$state`, `$derived`, `$effect`, `$props`).
- TypeScript (strict), checked by `svelte-check`.
- Tailwind CSS v4 via `@tailwindcss/vite`; the stylesheet is `src/routes/layout.css`,
  the brand color token `--color-brand` is defined there.
- Vite 7 for dev/build, Vitest 4 for tests.
- Icons from `lucide-svelte` (the only runtime dependency in `package.json`).
- Deploy target: Cloudflare Workers via `@sveltejs/adapter-cloudflare`
  (`svelte.config.js`) and Wrangler (`wrangler.jsonc`).

## Install

This repo uses pnpm as the primary package manager: `pnpm-lock.yaml`,
`pnpm-workspace.yaml`, and `.npmrc` (`engine-strict=true`) are present. A
`package-lock.json` also exists, so npm works too.

```sh
pnpm install
```

`pnpm-workspace.yaml` declares the single package `.` and allows builds for
`esbuild`, `sharp`, and `workerd`.

## Commands

All scripts are defined in `package.json`. Run them with `pnpm run <name>`
(or `npm run <name>`).

- `dev` — `vite dev`. Start the dev server.
- `build` — `vite build`. Produces the Cloudflare Worker output.
- `preview` — `wrangler dev .svelte-kit/cloudflare/_worker.js --port 4173`.
  Preview the built worker locally. Run `build` first.
- `check` — `svelte-kit sync && svelte-check --tsconfig ./tsconfig.json`.
  Typecheck (Svelte + TS). This is the typecheck command.
- `check:watch` — same as `check` in watch mode.
- `lint` — `prettier --check . && eslint .`.
- `format` — `prettier --write .`.
- `test:unit` — `vitest` (watch).
- `test` — `vitest --run` (single pass).
- `gen` — `wrangler types`. Generates `worker-configuration.d.ts`.
- `prepare` — `svelte-kit sync`. Runs automatically after install.

### Tests

`vite.config.ts` defines one Vitest project named `server`: Node environment,
including `src/**/*.{test,spec}.{js,ts}` and excluding `src/**/*.svelte.{test,spec}.{js,ts}`.
`expect.requireAssertions` is enabled, so every test must make at least one
assertion. No test files exist yet.

## Constraints — do not break these

- Keep Svelte 5 runes usage. State is `$state`/`$derived`/`$effect`, props are
  `$props`. Do not reintroduce Svelte 4 stores/syntax.
- `tsconfig.json` is `strict` with `checkJs`; `check` must stay green.
- `worker-configuration.d.ts` is generated by `pnpm gen` and is gitignored, but
  `tsconfig.json` lists it under `types`. Run `gen` before typechecking if it is
  missing. `app.d.ts` relies on the generated `Env` type.
- The build output directory is `.svelte-kit/cloudflare` (referenced by both
  `wrangler.jsonc` `main`/`assets` and the `preview` script). Do not change one
  without the other.
- `wrangler.jsonc` pins `compatibility_date` and the `nodejs_als` flag, and binds
  routes to the custom domain `se-emulator.shironekodigital.com`. Do not alter
  deployment routing casually.
- Formatting is enforced: tabs, single quotes, no trailing commas, print width
  100 (`.prettierrc`). Run `format` before committing; `lint` runs
  `prettier --check`.
- `/static` is in `.prettierignore`; do not reformat it.
- The StreamElements API hosts and paths in `src/lib/api.ts` are external
  contracts. Do not change them unless the task is specifically about them.
- Do not add a backend that receives the user's JWT; the token stays in the
  browser by design.
